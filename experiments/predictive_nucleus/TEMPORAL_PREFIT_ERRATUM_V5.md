# G5 v5 pre-fit data-integrity correction (2026-11-04)

The original [frozen protocol](TEMPORAL_STUDY_V5.md) at `1c60ac9ed32c9b8b6c9567ec0dcc361b7b44da65` required an unverified false claim. Before any TRAIN decision or test-challenge outcome was accepted/published, code review found that generating the claim as `1-current_truth` would put a perfect inverse of the evaluator answer into a learner-visible but unverified message. This would allow a model to infer truth simply by inverting the source's content, independent of whether the present two-scalar candidate uses it. It also makes the two counterfactual worlds' post-probe assertions different for no grounded reason.

**Prospective correction:** derive the identical unverified assertion from the publicly known pre-epoch `local` value for both latent continuations, not from `current` or `variant`. Specifically `assertion=1-local`; it is false for the transient branch and true for the persistent branch, and remains untrusted in both. This preserves all other frozen settings, number of episodes, action/sensor histories, 8% physical noise, selected payoffs, public prefix equivalence, grid, evaluator gates and held-out partitions. Strengthen the paired-world invariant to require identical unverified assertion records.

This is an **implementation correction before scientific fitting/collection**: the original wording "a false unverified claim" is narrowed to "an unverified, possibly false claim" because a universally false claim cannot be identical across opposite-truth twins without accessing the truth label. The original protocol remains retained and is not silently rewritten. Any hosted runs of the pre-correction source, including potential TRAIN logs, are discarded as integrity-invalid and cannot be used for parameter selection. Fit exactly once on the corrected, published source; then publish weights before opening any challenge.

No outcomes were used to select this correction; it follows directly from the protected learner/gold boundary.
