## Smallest mechanism

Add a transformed-frame adapter around the unchanged `physical_ledger_v1.Ledger`.
The persistent hypothesis index denotes the ordered coordinate sign transforms
`((1,1),(1,-1),(-1,1),(-1,-1))`. Event-local physical action indexes are separate
metadata and may differ between observations of the same interpretation.

Bind the complete transport frame: version, language-state SHA, registry SHA,
world-state SHA, lexical identity, ordered transforms and intervention view.
Also bind the published source-shard SHA and endpoint encoding/count. The
adapter may use the existing engine's `actions` field to encode the ordered
sign coordinates, explicitly as hypothesis coordinates rather than physical
actions. This internal reuse must never alter the original ledger's interface
or reinterpret its existing checkpoints.

Persist the original prior and complete ordered deliveries. Each delivery
contains the original projection receipt and its observed endpoint. Preserve
evidence ID, prefix digest, ordered roster, local action menu, endpoint
encoding, action probabilities, native likelihoods, projected likelihoods,
frame and frame digest. Preserve supplied floating-point values; normalization
may occur only in the existing numerical update. No posterior is accepted
from serialized state: recovery replays observations in their recorded order.

Validate exact fields, types, finite probability dimensions and normalization,
three distinct participant handles, four distinct bounded local actions,
frame equality and hashes, `L = A @ N` within `1e-12`, and the registered
uniform-over-hypotheses action mixture within `1e-12`. These are receipt
integrity checks, not inference of physical laws or participant roles.

An identical ID and complete payload is an idempotent no-op, including at
capacity. Reusing an ID with a different endpoint, prefix, likelihood or local
metadata rejects before mutation. Cross-frame evidence rejects even when
matrix dimensions match. Input and snapshot mutation must not affect retained
state. A valid zero-support observation remains recorded, with an unavailable
belief and the first failed evidence ID retained. Reuse the base atomic
explicit-checkpoint writer and its bounded loading contract.

The externally expected source digest and frame establish the caller's
provenance boundary. This adapter does not authenticate a model independently
of those supplied bindings, infer duplicate observations with different IDs,
or provide concurrent writers, automatic crash journaling or power-loss
durability beyond the existing successful explicit-checkpoint contract.

## Native recovery bank

Use all five fits, both laws and all three mapping views. Each of ten shards
contains 768 trials and three views: **23,040 trial/view contexts** in total.
For each context, use the three saved prefix-only projections and only the two
actually observed demonstration endpoints. Verify raw-shard hashes against
the pinned published manifest and public evidence IDs/endpoints against the
published public bank. Verify each frame against the raw model metadata and
the frozen transform/view inventory. Do not rerun models or score correctness.

Use three separate interpreter processes per complete qualification, with
only checksummed files communicating retained state:

1. **Produce:** create a fresh ledger, add the first observation, compare its
   belief to the published first-evidence reference, and save an explicit
   checkpoint for every context. Record externally held checkpoint hashes.
2. **Resume:** load every checkpoint using its expected hash, frame and source.
   Reproduce the first-evidence belief and target forecast. Fork retained and
   reset branches independently for all three existing query fees. Reproduce
   each published ask/action/value decision, consumed IDs, final posterior and
   target distribution; add the second endpoint only in purchased branches.
   Confirm the common parent remains unchanged. Independently deliver the
   second endpoint to the canonical retained ledger and save its checkpoint.
3. **Recover:** in a new process load every completed checkpoint, reproduce
   retained belief and target forecast, and verify exact ordered provenance
   and checkpoint round-trip bytes. Exercise identical duplicates and
   conflicting payloads after recovery, requiring state and checkpoint bytes
   to remain unchanged.

Native conflicts include altered prefix, observed endpoint and local roster
metadata under an existing evidence ID. Synthetic checks additionally cover
every frame binding, transformation order, malformed probability/shape/menu,
projection mismatch, caller mutation, capacity, corrupted/hash-mismatched
checkpoints, persisted duplicate IDs, zero-support continuation and inherited
checkpoint-write failure behavior. Expensive/unavailable branches preserve
their purchased histories exactly as published, including adverse controls.
