# Foundation Proof Corrective Amendment

**Status:** approved implementation direction, 2026-09-07; no phase admission.
**Scope:** `hybrid_mvp/`; repository-root adoption remains separately reviewed.

The user approved the September 7 goal/foundation audit and directed that stale
documentation be corrected before fixes. This amendment is subordinate to
`AGENTS.md` and takes precedence over conflicting closure sequencing and narrow
unresolved-designation instructions. It preserves the August 29 R4.1 data and
supervision protections and the August 2 semantic-algebra contract.

## 1. Goal and proof boundary

The MVP must preserve meaning in bounded conversations, reason from attributable
evidence, clarify uncertainty, learn authorized aliases and reuse them, and
produce readable faithful responses. A later learned pilot must independently
demonstrate compositional generalization within measured resource bounds.

Keep four judgments separate: graph validity, intended-meaning correspondence,
evidential support, and permission/current executability. Neither an accepted
program nor a proof of a different proposition establishes a correct answer.
Same-parser round-trip equivalence establishes consistency under that parser;
human meaning correspondence also needs independently specified contrasts.

Five persistent operators remain fixed. Programs remain construction lineage;
canonical expressions own derivation-independent semantics. This amendment
introduces no runtime phase, validation tier, implicit authority or admission.

## 2. One current execution route

The [foundation implementation plan](../plans/2026-09-07-foundation-proof-implementation-plan.md)
owns current work. The September 3 fixed closure and narrow unresolved-designation
design/plan are historical evidence, not instructions to stop after the first
unrelated phrase failure. Reuse their independently valid acyclic frame and
canonical designation work; do not discard it or treat it as a complete loop.

Inspect the complete foundation case matrix before selecting repair dependencies.
Record missing capabilities together. Repair the earliest owners; do not expand
corpora or change training epochs to compensate for missing representations.
The already-reproduced question-to-atom-kind defect is the one initial
containment exception: Task 2 may retire that false answer before the complete
matrix is executable. Broader capability repairs are selected after Task 3's
matrix; containment does not establish usable query support.

Bulk R4.1 authoring, review/export, purpose allocation, realization-recipe review,
corpus expansion and package publication remain frozen. R5 training, selection,
calibration, frozen evaluation and realization activation remain unavailable
until fresh R4.1 admission. No historical review selection is gold by default.

The foundation proof is development evidence before R4/R5 admission. It permits
an explicitly diagnostic compositional response reference through existing
semantic owner APIs. That reference must not be a product fallback, record
normal verified focus without the existing equivalence checks, masquerade as
learned output, or become a second semantic runtime. Its construction rules must
preserve roles, scopes, reference perspective, provenance and uncertainty.

Thus usable *diagnostic* behavior can be investigated before R5; normal learned
realization and its empirical claims still require R4/R5 admission. A learned
pilot may run only after a reviewed, isolated data authorization satisfies the
existing R4.1 data boundary. This amendment does not itself grant that access.

## 3. Semantic acceptance contract

Independent test expectations must specify initial context/facts, admissible
interpretations, requested information, forbidden readings, permitted mutations,
response meaning and acceptable human-readable wording. Runtime/bootstrap output
is diagnostic material, never the author of its own gold.

The initial contrast families are:

- definition/description versus identity, type-membership and location queries;
- lexical lookup with an unresolved target versus missing knowledge about a
  known target;
- subject/object reversal and polarity;
- event claim versus directive versus capability query;
- speech-history queries and context-dependent fragments;
- independent understood clauses alongside unresolved evidence;
- attributed/conditional content versus unconditional assertion/execution;
- an explicitly specified permitted operation versus the same denied operation;
- unknown-expression clarification, authorized existing-target alias learning,
  restart and unseen composition; new-identity acquisition remains separate.

`What is X?` does not uniquely prove lexical lookup. Preserve context-sensitive
alternatives. Interrogative features may constrain an answer domain but cannot
create an ontology kind. A learned unknown must not default to `concept`.

Definition or description support requires actual relevant semantic content.
The `AtomRecord.kind` of a concept is not its definition. The former synthesis
of `op:type(subject=concept:X, type=literal("concept"))` from a generic question
is explicitly retired as an incorrect interpretation. Remove its builder and
verification exceptions and its automatic query support. Explicit ordinary
world type facts remain valid; introspection, if later supported, requires its
own correctly expressed query/evidence rather than this implicit substitution.
The same retirement applies to corpus compilation: a `defines` assertion with
only a target and its registry kind cannot author definition gold. Reject it
as missing semantic content; retain the source as historical evidence until a
properly reviewed replacement supplies the requested meaning.

The input-pack `define` interrogative cue was part of that retired path: it
creates an answer variable without a reviewed meaning for the defining request.
Retire that cue rather than compensating with downstream copula/orthography
rules. Until its semantic affordance exists, retain typed unresolved evidence.
This is not a general retirement of genuine interrogatives, ordinary nominal
predicates, designation questions or the eventual definition capability.

A first containment test may prove that the false answer is no longer emitted.
It is not a completion test. Until a genuine definition/query projection exists,
the missing owner must remain visible; neither abstention nor a generic surface
may be counted as useful definition support. Preserve separate open-query and
response acceptance obligations in the plan.

## 4. Unknown meaning and learning

Preserve exact literal evidence, known grammatical relationships, context,
candidate senses/kinds and unresolved obligations. Lookup does not mutate.
Claims, teaching directives, learned-event claims and reviewed acquisition are
distinct. Existing-target aliases inherit target affordances without language-pack
regeneration; genuinely new identities require acquisition policy.

Known subgraphs can support interpretation/clarification while unresolved roles
continue to block affected execution. Do not remove an enclosing scope or admit
an embedded proposition as world truth merely to preserve a local clause.

Later research is a bounded, permissioned evidence consumer, not grounding or
automatic authority. Preserve source/sense/version and conflicts; do not send
private dialogue to a public lookup unnecessarily. Failed research can leave a
tracked unresolved inquiry. No network adapter is authorized by this increment.

## 5. Performance and anti-bloat

Retain current RuntimeConfig limits. Do not raise search caps or accept truncated
search merely to pass an example. Distinguish program derivations from meanings;
partial-state equivalence must preserve future legal continuations and evidence
ownership before it may reduce search duplication.

Replace whole-store query materialization with indexed relevant retrieval where
the measured owner requires it. Measure rows visited, states and inference work,
not just output count. Cache generation-static validation/indexes at activation.
Do not add per-example validators, extra approval workflows or whole-bundle
checks to the normal cycle. Use the existing test/inventory/validation owners.

## 6. Tests, generated artifacts and authority migration

Preserve immutable test inventory and historical ledger identities. The user's
subsequent explicit test-cleanup approval permits deleting redundant or obsolete
test bodies after identifying their exact current replacements. Historical source
and metadata remain recoverable from Git (pre-cleanup checkpoint `add3917`), not
required as permanently collectable stale tests. Preserve valid assertions through
explicit same-assertion successors with truthful current expectations. Supersession
chains may be shortened across deleted intermediates only when retained ancestry,
assertion identity and phase coverage remain intact. Never refresh a frozen AST
or silently drop a valid obligation to hide a changed contract. Later source
metadata and selectors are refreshed through the existing tools.

Replace stale routing assertions with successors that verify this amendment's
precedence and historical classifications. Do not retain tests whose only purpose
is to force the retired atom-kind answer. Preserve role, scope, provenance,
authority, learning transaction and denied-effect protections.

Generated-form/ABI changes require identification of their source owner,
preservation of authorized realization fields and semantics, deterministic
regeneration and relevant regression checks. This amendment retires only the
incorrect question-to-atom-kind interpretation, not any correctly authorized
response behavior. It does not broadly waive realization preservation.
